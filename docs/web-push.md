# Уведомления в браузер о заказах за Счёт Шефа (T-509)

ТЗ 16.10, п. 4.2: каждый заказ, закрытый в iiko типом оплаты «Счет Шефа», приходит
уведомлением на телефон или компьютер учредителя. Работает через стандартный
Web Push: без Telegram, без сторонних сервисов и без приложения из магазина.

## Как включить

Кабинет учредителя (`/founder`):

* **Компьютер** — блок «Счёт Шефа · iiko» → «Уведомления о Счёте Шефа» → «Включить».
* **Телефон** — кружок профиля в шапке → «Включить».

Браузер спросит разрешение. После включения есть «Проверить» (проверочное
уведомление) и «Выключить». Подписка — на устройство: телефон и ноутбук
включаются каждый у себя. Включить могут учредитель и администратор.

| Устройство | Что нужно |
|---|---|
| Android: Chrome, Edge, Firefox, Samsung Internet | ничего, включается во вкладке |
| Windows, macOS, Linux: Chrome, Edge, Firefox | ничего, включается во вкладке |
| Mac: Safari 16.1+ (macOS 13+) | ничего, включается во вкладке |
| iPhone / iPad: iOS 16.4+ | только из значка: Safari → «Поделиться» → «На экран „Домой“», открыть Retro Milliy со значка, включить там. Во вкладке Safari кабинет показывает эту подсказку |

Если разрешение когда-то отклонили, повторно браузер не спросит. Кабинет это
показывает и подсказывает, где снять запрет (Safari → Настройки → Веб-сайты →
Уведомления; на iPhone: Настройки → Уведомления → Retro Milliy).

## Когда приходит

Сервер раз в две минуты читает из iiko заказы «Счёт Шефа» за вчера и сегодня.
В отчёт iiko заказ попадает, когда его закрыли оплатой, поэтому уведомление
приходит в течение двух минут после закрытия счёта, а не при пробитии блюда.

Пример:

```
Счёт Шефа · стол 12
Плов «Ретро» ×2, Чай чёрный ×2
184 000 сум · Музаффар
```

Нажатие на уведомление открывает кабинет учредителя.

* Каждый заказ приходит один раз. Журнал — таблица `founder_chef_order_pushes`.
* Самый первый запуск (журнал пуст) только запоминает уже закрытые заказы. Иначе
  после выката пришла бы пачка уведомлений за весь день.
* Заказы, закрытые, пока ни одно устройство не подписано, в журнал записываются
  (`no_recipient`). Включённые позже уведомления старое не присылают.
* Устройство отписалось или сбросило браузер, и служба отвечает 404/410 —
  подписка удаляется сама.

## Настройка сервера

Ничего обязательного. Ключ VAPID сервер создаёт при первом старте и хранит в базе
(`push_vapid`), подписки — в `push_subscriptions`. Необязательные переменные:

* `VAPID_PRIVATE_KEY` — свой ключ (`python -m retro.web_push`). Смена ключа
  отменяет все подписки: устройства включаются заново.
* `VAPID_SUBJECT` — контакт для служб доставки, `mailto:` или `https:`. По умолчанию
  `DASHBOARD_PUBLIC_URL` (или `RAILWAY_PUBLIC_DOMAIN`).

Обработчик уведомлений — `/sw.js` (открыт без входа, секретов в нём нет). Он
только показывает уведомления: запросы страниц не перехватывает и ничего не кеширует.

## Как проверено (17.10.2026)

* Шифрование (RFC 8291) расшифровывает независимая библиотека `http-ece`, подпись
  VAPID проверяется ключом сервера (`tests/test_web_push.py`, SQLite и Postgres).
* Настоящие службы доставки принимают подпись: Apple (`web.push.apple.com`, Safari)
  отвечает «BadWebPushToken» на выдуманное устройство и «BadJwtToken» на битую
  подпись; Google FCM — 410 против 403. Подпись прошла их проверку.
* Google Chrome 153 с чистым профилем: «Включить» → подписка через FCM →
  «Проверить» и заказ «Счёт Шефа» пришли, расшифрованы и показаны.
* На реальном iPhone ещё не проверено: на Linux Safari нет. Шаги — выше в таблице.
