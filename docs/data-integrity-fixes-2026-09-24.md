# Исправления целостности данных — T-368

Основание: [аудит](data-audit-2026-09-24.md). Исходные воспроизведения ошибок сохранены в commit `759131b` (код приложения там соответствует `c31e697`). Текущий `scripts/reproduce_data_audit.py` запускает регрессии правильного поведения. Production-базы не мигрировались и не исправлялись вручную.

## Что изменилось в цифрах

Контроль iiko только на чтение, 14–23 сентября 2026:

| Величина | Сумма, сум |
|---|---:|
| Продажи по согласованным направлениям, до исключения групп меню | 477 809 457,00 |
| Меню после локально настроенных исключений | 448 531 957,00 |
| Контейнеры | 2 905 500,00 |
| ДОСТАВКА ЯНДЕКС | 26 372 000,00 |
| Продажи вне согласованной банкетной выборки | 20 126 643,00 |
| Выборка учредителя: PAYMENT обычных заказов + все операции отмеченных банкетных блюд | 462 799 456,79 |
| Та же выборка, независимый отчёт с PayTypes | 462 799 456,82 |
| Фактическая разница независимых отчётов | 0,03 |
| Яндекс, оплаты по согласованной выборке | 27 031 000,00 |
| Яндекс, меню после исключений | 659 000,00 |

Верхняя цифра директора теперь включает исключённые группы. Маржа и детализация меню продолжают использовать меню после исключений; рядом указаны суммы исключений. Поэтому изменения фильтра меню не уничтожают продажи в заголовке. Это всё ещё согласованная выборка направлений: 20 126 643 отдельно обозначены как продажи вне банкетного правила. Production может иметь дополнительные исключения (в аудите — «Без группы»); API возвращает фактически активный список.

Кассовая смена сопоставляется с PAYMENT **всей кассы**, а не с более узкой карточкой ресторана. Синтетический пример: 100 продаж ресторана + 60 банкета, получено 200 → оценка новых авансов 40, прежде получалось 100. Живые проверки: 15 сентября — оценка 600 000, в том числе наличными 600 000; 23 сентября — 63 250 000 / наличными 28 050 000. «Приход всей кассы» берётся из полного итога смены, а не из смешанных областей отбора.

| C1 | В кассовом расчёте запрашиваются свежие OLAP; смена и продажи всё равно не являются транзакционным снимком iiko, поэтому оценка авансов не становится verified. |
| C2 | Snapshot содержит версию расчёта, эффективные исключения и пределы кэша. Это не точное время каждой записи источника. |

| C7 | Агрегация по имени остаётся особенностью текущего OLAP-контракта. Совпадающие имена нельзя достоверно разделить без подтверждённых стабильных идентификаторов источника; исторические суммы не переразмечаются по догадке. |

| C10 | Сохранённые отчёты имеют отдельные неизменяемые версии, новая генерация не переписывает старый PDF. Хранение ограничено настроенным retention (число версий). Старые PDF не пересчитываются. |

Дополнительно: черновая нехватка учитывает накопленный зарплатный долг и текущий черновик; при неизвестных деньгах/начислениях она остаётся неизвестной. Импорт реестра читает строки ниже 78 и запрещает подмену человека под существующим ID строки. PDF показывает точные контрольные суммы и границы выборки рядом с округлёнными карточками.

## Проверка пользовательского пути

Локальный Chrome, `http://127.0.0.1:8768`, отдельные тестовые SQLite, без записи в production:

- Начисление 100 000 подтверждено через новую форму → долг 100 000.
- Выплата 40 000 → деньги 1 000 000 → 960 000, долг 100 000 → 60 000, выплачено 40 000; API 201.
- Директор показывает 477 809 457, меню 448 531 957 и обе исключённые группы; Яндекс оплаты 27 031 000 / меню 659 000.
- Учредитель показывает отдельный охват всех продаж и независимую сверку.
- После остановки локального сервера выбор 24 сентября скрывает суммы 23 сентября и показывает ошибку, не оставляя старые цифры под новой датой.

Регрессии: `python -m pytest -q`; `node --test tests/js/*.test.mjs`; compileall, синтаксис всех JS, diff-check и проверка tracked secrets. Отдельно проверены повторы POST, прерванная запись, несовместимый payload одного ключа, изменения источника между страницами, изменение расходов перед XLSX, нулевые дни и знаковые возвраты. Исторические данные production требуют отдельной сверки: исправленный код не может восстановить потерянные ставки, разнести старые выплаты по людям или доказать принадлежность авансов отделению.
