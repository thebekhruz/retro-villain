# Отклик и ожидание в панели (busy.js)

Бухгалтер менял число в «Финансах дня», и загрузка шла без опознавательных
знаков: непонятно, ушло ли число, идёт ли запись, не сломалось ли. Отсюда —
один язык отклика для всех модулей. Код: `retro/static/busy.js`, стили —
блок «ОТКЛИК И ОЖИДАНИЕ» в `retro/static/style.css`. Подключён на всех
страницах первым скриптом.

## Принципы

1. **Каждое нажатие отвечает сразу (< 100 мс).** Кнопки, чипы, вкладки,
   ячейки «проседают» (`:active`, scale .97); большие строки и заголовки
   секций не сжимаются, а темнеют. С клавиатуры виден золотой фокус.
   Всё это — CSS, модулю делать ничего не нужно.
2. **Ожидание — там, где оно происходит.** Не общий спиннер на экран, а
   крутится та кнопка, то поле, та строка, что начали действие.
3. **Быстрое не мигает.** До 250 мс видно только нажатие и итог ✓.
   Показанный спиннер держится не меньше 350 мс.
4. **Итог — на месте.** Кнопка: ✓ на ~0,9 с. Поле: зелёная галочка и
   подсветка строки. Ошибка: красная рамка и текст под полем, введённое
   остаётся — можно исправить и повторить. Тост (`RetroToast`) — как и был,
   общий итог внизу экрана.
5. **Не отправленное видно.** Число набрали, но Enter / уход из поля ещё не
   было — поле кремовое с золотой чертой и значком ↵.
6. **Перезагрузка не опустошает раздел.** Данные на месте, слегка гаснут и не
   нажимаются; сверху тонкая золотая полоса. Первая загрузка — скелет в форме
   содержимого, без «Загружаем…» и без прыжка раскладки.
7. **Размеры не прыгают.** Спиннер рисуется поверх подписи (ширина кнопки та
   же), значки поля — фоном у свободного края.
8. **Двойного действия нет.** Пока кнопка в работе, повторное нажатие и
   отправка формы не проходят. Деньги по-прежнему пишутся через
   `RetroFinancialWrite` (ключ идемпотентности) — busy.js его не заменяет.

## API

Все функции принимают элемент и обещание (или функцию, которая его вернёт) и
**возвращают то же обещание** — цепочку модуля ничего не меняет. Обещание,
которое разрешилось `false`, считается неудачей (так отвечает `run()` в
accountant.js).

| Что | Вызов | Что видно |
|---|---|---|
| Кнопка | `RetroBusy.button(btn, promise, {done})` | блок сразу, спиннер после 250 мс, ✓ при успехе (`done:false` — без ✓) |
| Поле с автосохранением | `RetroBusy.field(input, promise, {row, message})` | спиннер в поле, галочка + подсветка строки; ошибка — рамка и текст под полем |
| Строка | `RetroBusy.row(el, promise, {collapse})` | золотая кромка и приглушение; успех — вспышка; `collapse` — свернуть удалённую |
| Вспышка «записано» | `RetroBusy.flash(el)` | зелёная подсветка на 1,6 с |
| Перезагрузка раздела | `RetroBusy.section(el, promise)` | раздел гаснет после 250 мс, `aria-busy` |
| Первая загрузка | `RetroBusy.skeleton(container, {rows, cols, variant})` | полосы-заглушки; модуль потом просто перерисует контейнер |
| Полоса вручную | `RetroBusy.track(promise)` | для ожиданий не через `fetch` |
| Фоновые запросы | `fetch(url, {retroBusy: false})` или `RetroBusy.silent(() => { p = load(); })` | полоса не зажигается; `silent` глушит только запросы, начатые синхронно внутри fn (после `await` — уже нет), чтобы не гасить полосу нажатиям человека |
| Сброс | `RetroBusy.clear(prefix, state?)` | забыть состояния (смена дня/месяца); `clear('', 'error')` в начале нового действия снимает старые красные поля |

Верхняя полоса включается **сама** для любого `fetch` к `/api/` дольше 250 мс.

### Перерисовка и `data-busy-key`

Модули перерисовывают таблицы целиком. Чтобы «сохраняю / ✓ / ошибка»
пережили перерисовку, у элемента ставят устойчивый ключ — новый узел с тем же
ключом получает состояние (и введённое значение) сам:

```js
input.dataset.busyKey = 'pay:' + day + ':' + employeeId + '@' + shiftDay;   // включает дату/месяц
line.dataset.busyKey = 'shift:' + day + ':' + employeeId + '@' + shiftDay;
```

Ключ должен пережить и само действие: id строки, который меняется от записи
(например, «e<сотрудник>» → «a<начисление>» после подтверждения смены), для
ключа не годится — берите сотрудника и день.

Поле с ключом ещё и показывает «не отправлено», пока набранное отличается от
сохранённого.

## Примеры

```js
// Кнопка формы
form.addEventListener('submit', event => {
  event.preventDefault();
  RetroBusy.button(form.querySelector('[type=submit]'), save());
});

// Число в ячейке сохраняется по Enter / уходу из поля
input.addEventListener('change', () => RetroBusy.field(input, write(url, body), {row: line}));

// Удаление строки: строка «в работе», потом плавно сворачивается
RetroBusy.button(x, RetroBusy.row(line, remove(id), {collapse: true}), {done: false});

// Смена даты: прежние данные гаснут, пока идут новые
RetroBusy.section($('layout'), loadDay());

// Excel: кнопка в работе, пока файл не начал скачиваться
RetroBusy.button(button, (async () => { const blob = await (await fetch(url)).blob(); save(blob); })());

// Фоновый опрос — без полосы
setInterval(() => fetch('/api/…/status', {retroBusy: false}), 5000);
```

Первая загрузка — скелет прямо в разметке (`.rm-skel`, `.rm-skel-row`,
`.rm-skel-card`) или `RetroBusy.skeleton(...)`; статус в шапке —
`<span class="top-status rm-status-skel" id="connection"></span>` (пустой
статус рисуется полосой).

## Проверка

- `node --test tests/js/busy.test.mjs` — чистые помощники (порог полосы,
  «не отправлено», минимальное время спиннера) и подключение на страницах.
- Посмотреть глазами — стенд с задержкой ответа (`STAND_DELAY_MS=800`).
- Текст на экране идёт через словарь `i18n-uz.js`; busy.js своих надписей не
  рисует, кроме запасного «Не сохранено. Проверьте и повторите.».
