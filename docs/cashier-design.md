# Retro Milliy: модуль кассира

> Обновление 16.09.2026: первоначальный охват «весь филиал» ниже заменён
> разделением по кассе и отделению. Актуальные правила и проверенные суммы —
> в README, раздел «Значения». В XLSX попадают только операции PAYMENT кассы
> Retro без школы и отделения «Бехруз (Свадьба)».

Согласованный объём: Python backend, мобильная веб-страница, выбор дня
(сегодня в Asia/Tashkent), продажи после скидок, количество чеков, способы
оплаты и скачивание XLSX по предоставленному шаблону. Весь филиал.
Зарплата, прочие расходы, инкассация и предоплаты не автоматизируются в MVP.
Остаток кассы не рассчитывается без этих данных. Остальные два модуля не
реализуются и не получают выдуманных названий.

FastAPI обслуживает статический интерфейс и API. Модуль cashier владеет
моделью снимка и экспортом. Адаптер integrations/iiko.py переносит read-only
запросы из Apps Script «Retro Milliy — iiko отчёт», прочитанного 16.09.2026.
Секреты только на сервере: переменные окружения или build/.env (build уже
gitignored). Подключение разрешено только к https://retro3158.iikoweb.ru.

Продажи: DishDiscountSumInt. Чеки: UniqOrderId.OrdersCount из отдельного
итога по OpenDate.Typed, не сумма по типам оплат. Поле чеков найдено также
в src/modules/revenue/iiko.ts исходного retro-protagonist. До live-проверки
совместимость этого дополнительного поля не считалась подтверждённой.
16.09.2026 live-проверка за 10.09 подтвердила поле: 279 чеков,
45 196 900 сум; сумма по всем группам оплат совпала с дневным итогом.
После уточнения пользователя 16.09.2026 используем PayTypes, не PayTypes.Combo:
iiko возвращает отдельные суммы для каждого способа, включая доли смешанных
чеков. Семь названий и их порядок соответствуют пользовательскому скриншоту.
Демо остаётся Демо. Опечатка источника «Яндех Еда» → «Яндекс Еда».
Удалённые заказы/позиции исключены, как в рабочем Apps Script.

Выручка итога сверяется с оплатами с допуском 1 сум. Несогласованные и
неполные ответы не показываются как нули. Экспорт использует тот же снимок,
что открыт на экране. Истёкший/чужой снимок требует обновления.
Демонстрационные данные доступны только в явно отмеченном режиме.

Excel сохраняет внешний вид первого листа, но очищает все старые операции.
Нереализованные расчёты не выдаются за результат. Количество и средний чек
добавляются слева. Лист «Касса» содержит полную сверяемую расшифровку оплат.
Все семь источников автоматически заполняются в C3:D9 первого листа, итог D11.
Ручное соответствие в окружении удалено. На листе «Касса» добавлена доля.
Новый неизвестный источник блокирует экспорт, а не теряется из общего итога.

Сервер по умолчанию доступен только локально. Для внешнего использования
нужны HTTPS и настроенные DASHBOARD_USER/DASHBOARD_PASSWORD. Без них
запросы с нелокального адреса отклоняются. Публичного деплоя в этой задаче нет.
