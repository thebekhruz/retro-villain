# Cashier implementation plan

**Goal:** рабочий мобильный модуль кассира и XLSX по шаблону.
**Architecture:** FastAPI, адаптер iikoWeb, модуль cashier, статический UI.
**Tech Stack:** Python 3.11+, FastAPI, httpx, openpyxl, pytest, HTML/CSS/JS.
**Spec:** ../../cashier-design.md

## Global constraints
- Только Retro Milliy, read-only iiko, без секретов в git или браузерном коде.
- Asia/Tashkent; весь филиал; расходы и остаток кассы исключены из MVP.
- Нет подмены отсутствующих данных нулями или демонстрацией.

## Implementation (in this session)
- [x] tests/test_cashier.py: независимые примеры сумм, чеков, расхождений,
  пустого дня, нечисловых данных, XLSX без исходных операций.
- [x] retro/integrations/iiko.py: auth/init/poll из Apps Script; строгие
  ответы, ограниченные повторы, безопасные ошибки без тела/токена.
- [x] retro/modules/cashier/service.py: итог из отдельного запроса,
  сверка оплат, bounded cache снимков для экрана и экспорта.
- [x] retro/modules/cashier/export.py: сохранение макета исходного файла,
  очистка данных примера, полная расшифровка на «Касса».
- [x] retro/app.py: API даты/данных/экспорта; локальный доступ, Basic Auth
  для защищённого развёртывания; no-store для финансовых ответов.
- [x] retro/static/: мобильный интерфейс, выбор дня, явные состояния
  загрузки/ошибки/пустого дня, отключение экспорта устаревших данных.
- [x] Проверить pytest, API, Excel, браузер 390px и desktop. Live iiko
  проверять только при наличии доступа; иначе явно передать ограничение.
