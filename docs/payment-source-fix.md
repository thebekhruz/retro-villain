# Выручка по отдельным типам оплаты — 16.09.2026

Пользователь уточнил ровно семь названий по скриншоту. Демо не считать
наличными. Список должен совпадать в UI и Excel, первый лист должен быть заполнен.

Причина старой ошибки: PayTypes.Combo группировал чеки по комбинациям,
а обязательный IIKO_PAYMENT_CELLS оставался пустым. Одна настройка соответствий
не решила бы неправильное распределение сумм смешанных чеков.

Исправление: PayTypes возвращает суммы каждого отдельного типа непосредственно
из iiko. За 15.09.2026 получены и сверены с отдельным итогом:

| Источник | Сумма, UZS |
|---|---:|
| Демо | 37 329 000 |
| UzCard | 7 118 500 |
| Наличные (Инкасса QR) | 4 346 000 |
| Xumo | 2 632 500 |
| Я Rahmat | 3 939 000 |
| Яндекс Еда | 1 135 000 |
| Click/Payme Безналичный перевод | 1 784 000 |
| Итого | 58 284 000 |

204 чека. Источник имеет опечатку «Яндех Еда», отображаем «Яндекс Еда».
Нулевая служебная строка «(без оплаты)» не является источником выручки.
Неизвестные источники не отбрасываются молча — отчёт возвращает ошибку.
Итоги первого листа и доли второго просмотрены после пересчёта LibreOffice.
22 автоматические проверки прошли. Исходные расходы остаются вне scope.
Служба retro-cashier перезапущена, доступ по-прежнему только 127.0.0.1.
